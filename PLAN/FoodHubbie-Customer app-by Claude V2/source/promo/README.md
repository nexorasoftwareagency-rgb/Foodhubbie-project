# FoodHubbie — Promotion Workspace

Everything about getting restaurants onto FoodHubbie lives here: what we're posting, where, what's done, what's blocked on the owner, and what it produced.

## Files

| File | What it is |
|---|---|
| `TRACKER.md` | **Single source of truth.** One row per channel with status, next action, result. Append to the log after every action. |
| `COPY.md` | Paste-ready copy for every channel. Don't improvise claims — edit here first, then paste. |
| `ASSETS.md` | Image inventory + which asset goes to which channel + how to regenerate. |
| `assets/` | Generated images (Product Hunt gallery, logo, social card). |

## Ground rules (non-negotiable)

1. **No "zero ban risk" / "guaranteed" claims.** WhatsApp wording is: official Meta Cloud API, opt-in audiences, Meta-approved templates, paced sends, STOP honoured, Meta still controls approval and standing.
2. **No invented testimonials, logos or customer counts.** If there is no proof, there is no proof section.
3. **Pricing, exactly:** POS counter ₹1 · QR table ₹2 · WhatsApp order ₹5 (or 1% of that order's value on the commission option — a choice, not "whichever is lower") · promo message ₹1 (our fee; Meta bills its conversation charges separately) · one-time setup ₹500, non-refundable, adjusted in the first bill · no monthly fee, no minimum, no lock-in · cancelled/refunded orders never billed.
4. **Never post a screenshot with a real customer's phone number or email.** Admin shots use `owner@foodhubbie.app`; chat lists are pixelated or not used at all.
5. **One link per post**, to a page that answers the reader's question (usually `/pricing`, `/qr-ordering` or the homepage).
6. Answer threads before dropping links. A cold link in a stranger's thread costs more reputation than it earns.

## Status vocabulary

- `READY` — copy + asset exist, posting is a 2-minute job.
- `BLOCKED` — needs something only the owner can do (account, login, payment, decision).
- `LIVE` — published; result column starts filling.
- `SKIP` — considered and rejected, with the reason recorded.

## The weekly ritual (60–90 min, same day each week)

1. Post from `COPY.md` for the week (X + Threads at minimum).
2. Spend 20 min replying to restaurant/hospitality threads — help first, link only if asked.
3. Update `TRACKER.md`: status, date, link, and one line of result (views / clicks / replies / demos).
4. Fill the weekly KPI row in `TRACKER.md`.
5. Pick next week's single experiment from the `TODO` rows — one, not five.

## KPI definitions (only these count)

| Metric | How we know | Why it matters |
|---|---|---|
| Qualified conversations | A restaurant owner/decision-maker replies and describes their operation | The only leading indicator that isn't vanity |
| Demo bookings | `/book` submission or a confirmed call | First real commitment |
| Demos completed | Call happened | Where the product is actually judged |
| Trial signups | `/signup` request approved | Pipeline |
| Paying outlets | First invoice paid | The only metric that funds the next month |

Followers, likes and impressions are recorded but are **not** goals.

## Stop rule

Carried over from `docs/PLAN-PROMOTE-SAAS.md`: if ₹5,000 of spend (or 4 weeks of full effort on paid promotion) produces **zero demos**, stop promoting and go back to walk-in selling until the offer or the demo flow changes.

## What this folder does NOT cover

- Legal/commercial terms (MSA, DPA, entity name) — needs a lawyer.
- Paid ads — gated behind a case study, per the plan.
- Country-specific pricing — site is India-only on purpose.
